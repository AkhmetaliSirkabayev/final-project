# Git — шпаргалка

Краткий справочник по основным командам терминала, Git и GitHub.

## 1. Навигация по терминалу

| Команда | Описание |
|---|---|
| `pwd` | Показывает путь к текущей рабочей директории. |
| `ls` | Показывает содержимое текущей папки. |
| `ls -a` | Показывает все файлы, включая скрытые. |
| `cd first-project` | Переходит в папку `first-project`. |
| `cd first-project/html` | Переходит в папку `html` внутри `first-project`. |
| `cd ..` | Переходит на уровень выше (в родительскую директорию). |
| `cd ~` | Переходит в домашнюю директорию пользователя. |
| `cd /` | Переходит в корневую директорию. |

## 2. Работа с файлами и папками

### Создание

| Команда | Описание |
|---|---|
| `touch index.html` | Создаёт файл `index.html`. |
| `touch index.html style.css script.js` | Создаёт сразу несколько файлов. |
| `mkdir second-project` | Создаёт папку `second-project`. |

### Копирование и перемещение

| Команда | Описание |
|---|---|
| `cp file.txt ~/my-dir` | Копирует файл в другую директорию. |
| `mv file.txt ~/my-dir` | Перемещает файл в другую директорию. |

### Чтение

| Команда | Описание |
|---|---|
| `cat file.txt` | Выводит содержимое текстового файла в терминал. |

### Удаление

| Команда | Описание |
|---|---|
| `rm about.html` | Удаляет файл `about.html`. |
| `rmdir images` | Удаляет пустую папку `images`. |
| `rm -r second-project` | Удаляет папку `second-project` вместе со всем содержимым. |

### Полезные возможности терминала

- `&&` — позволяет выполнить несколько команд последовательно, если предыдущая завершилась успешно.

```bash
mkdir project && cd project && touch README.md
```

- `↑` и `↓` — позволяют перемещаться по истории ранее выполненных команд.
- `~` — обозначает домашнюю директорию пользователя.
- `..` — обозначает родительскую директорию.
- `.` — обозначает текущую директорию.

# 3. Основы Git

**Git** — система контроля версий, которая позволяет отслеживать изменения в проекте, сохранять историю разработки и возвращаться к предыдущим версиям файлов.

### Основные понятия

- **Репозиторий (Repository)** — хранилище проекта со всей историей изменений.
- **Коммит (Commit)** — сохранённая версия изменений в репозитории.
- **Staging Area** — область подготовки файлов перед созданием коммита.
- **Ветка (Branch)** — отдельная линия разработки.
- **GitHub** — платформа для хранения удалённых Git-репозиториев и совместной работы.

## 4. Основные команды Git

### Инициализация репозитория

```bash
git init
```

Создаёт новый Git-репозиторий в текущей папке.

Чтобы удалить Git из папки, можно удалить скрытую директорию `.git`. Внимание: это удалит локальную историю Git и настройки репозитория.

### Проверка состояния репозитория

```bash
git status
```

Показывает текущее состояние репозитория:
- Изменённые файлы.
- Новые, ещё не отслеживаемые файлы.
- Файлы, подготовленные к коммиту.

### Подготовка файлов к коммиту

```bash
git add todo.txt
```

Добавляет файл `todo.txt` в область подготовки.

```bash
git add --all
```

Добавляет все новые, изменённые и удалённые файлы в область подготовки.

```bash
git add .
```

Добавляет изменения из текущей директории и её поддиректорий в область подготовки.

### Создание коммита

```bash
git commit -m "Initial commit"
```

Создаёт коммит — сохраняет подготовленные изменения в локальной истории Git.

Флаг `-m` (от англ. *message* — сообщение) позволяет указать описание коммита.

Примеры сообщений:

```bash
git commit -m "Add README"
git commit -m "Create User class"
git commit -m "Fix calculation bug"
```

### Просмотр истории коммитов

```bash
git log
```

Показывает подробную историю коммитов.

```bash
git log --oneline
```

Показывает историю коммитов в кратком формате.

# 5. Работа с GitHub

**GitHub** — удалённый сервис для хранения Git-репозиториев.

### Клонирование репозитория

```bash
git clone <repository-url>
```

Копирует удалённый репозиторий на компьютер вместе с историей коммитов.

Пример:

```bash
git clone git@github.com:username/project.git
```

### Подключение удалённого репозитория

```bash
git remote add origin <repository-url>
```

Связывает локальный репозиторий с удалённым репозиторием на GitHub.

`origin` — стандартное имя удалённого репозитория.

### Проверка удалённых репозиториев

```bash
git remote -v
```

Показывает адреса подключённых удалённых репозиториев.

### Отправка изменений на GitHub

```bash
git push
```

Отправляет локальные коммиты в удалённый репозиторий.

При первой отправке новой ветки может понадобиться:

```bash
git push -u origin main
```

Флаг `-u` связывает локальную ветку с удалённой. В дальнейшем обычно достаточно писать `git push`.

### Получение изменений с GitHub

```bash
git pull
```

Получает изменения из удалённого репозитория и интегрирует их в текущую локальную ветку.

# 6. Типичный порядок работы с Git

Обычный процесс сохранения изменений и отправки их на GitHub:

```bash
# 1. Переходим в папку проекта
cd ~/Documents/First-project

# 2. Проверяем состояние репозитория
git status

# 3. Подготавливаем изменения
git add .

# 4. Создаём коммит
git commit -m "Update project"

# 5. Отправляем изменения на GitHub
git push
```

### Как работают три основные команды?

| Команда | Действие |
|---|---|
| `git add` | Подготавливает изменения к сохранению. |
| `git commit` | Сохраняет изменения в локальной истории Git. |
| `git push` | Отправляет коммиты на GitHub. |

**Важно:** `git add` и `git commit` работают локально на компьютере. Только `git push` отправляет коммиты на GitHub.

## 7. Полезные дополнительные команды

| Команда | Описание |
|---|---|
| `git diff` | Показывает изменения в файлах, которые ещё не добавлены в Staging Area. |
| `git diff --staged` | Показывает подготовленные изменения. |
| `git restore file.txt` | Отменяет незастейдженные изменения в файле. |
| `git rm file.txt` | Удаляет файл и подготавливает удаление к коммиту. |
| `git branch` | Показывает локальные ветки. |
| `git switch main` | Переключается на ветку `main`. |
| `git switch -c feature` | Создаёт новую ветку `feature` и переключается на неё. |

---

**Рекомендация:** регулярно используй `git status`, чтобы контролировать состояние репозитория и понимать, какие изменения будут включены в следующий коммит.
